# System and file layout

<Lead>
  The playtest is a 64-bit Unity Mono build. Its managed game code, LuaJIT scripts, Burst code, and game data
  are separate parts of the installation.
</Lead>

## Runtime stack

- `Sanctuary.exe` and `UnityPlayer.dll` run Unity 6000.3.22f1.
- `Trebuchet.dll` contains the main managed game and tool code.
- Unity Entities and Burst implement parts of the simulation and rendering.
- LuaJIT runs separate host and client script states.

The map inventory follows the [maintainer-confirmed count of 150 maps](https://github.com/Remmyboy/sanctuary-unit-db/pull/1#discussion_r3931958747),
including 79 named maps and 71 generated `~FFA-*` and `~TEAM-*` maps.

The Lua inventory decreased from **702 to 590 files**, also confirmed in
[Remmy's build-update review](https://github.com/Remmyboy/sanctuary-unit-db/pull/1#pullrequestreview-5117900656).
The **367** loose `.santp` templates are under `engine\LJ\lua`; templates inside archives are counted separately.
`FilesCache.CreateFileCache` reads selected template/decal data from `Environment.sanpack` and UI data from `UI.sanpack`.

## Mod directories

The asset loader searches installation and user Mods directories. Create `Sanctuary_Data\Mods` before using
that path. See [asset overrides](./assets) for precedence.
