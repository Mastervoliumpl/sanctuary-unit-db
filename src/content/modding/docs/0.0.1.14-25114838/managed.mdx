# Managed code and DLL loading

<Lead>
  Trebuchet.dll remains readable managed code. Unity 6000.3.22f1, Mono runtime files, and Burst assemblies are
  present in the inspected installation.
</Lead>

## Assembly evidence

The assembly metadata identifies `Trebuchet` version 1.0.0.0 with no public key. That assembly version is
not the game's displayed version: Unity metadata identifies the game as 0.0.1.14.

ILSpy can resolve descriptive game types for Lua, logging, networking, assets, and map tooling. The generated
Lua delegate list has 667 entries. Inspect this build's types before reusing offsets, signatures, or patches
from the Unity 2022 snapshot.

## Loading and patching limits

The presence of readable methods does not establish that arbitrary plugin DLLs will be loaded. No managed
plugin activation workflow supplied by the game was verified in this inspection. The installed ModManager
package supplies a separate BepInEx loader and watches `SanctuaryMods` for DLLs. Its loading and hot reload
are third-party behavior, excluded from claims about shipped game support. See the
[package audit](./build-information#third-party-packages-excluded-from-game-findings).

Burst-generated paths can execute native code outside an ordinary managed method. A patching approach needs
runtime verification against the specific method and world it affects.

## Research order

Check the [shipped Lua interface](./lua/overview) first. If a required capability is missing, identify its
managed implementation and whether it runs in the host or client. Keep loader and patching experiments
separate from the verified reference until they have been tested.
