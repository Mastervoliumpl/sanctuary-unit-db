# Modding the current playtest

<Lead>
  The shipped build exposes readable Lua, data templates, asset override paths, map files, and debug settings.
  Start with Lua or data. Use managed-code changes only when the shipped interfaces cannot do the job.
</Lead>

<Callout title="Keep tests offline" warning>
  Lua changes must match the host's Lua hash before a client can join; a mismatch is rejected as "Incompatible
  game version." Template changes are not covered by that gate and can desynchronize a running match. Test
  simulation changes only with identical files on every machine.
</Callout>

## Use a reversible test cycle

<Steps>
  <li>Copy the original file and record the documentation version ID.</li>
  <li>Make one small, reversible change appropriate to the chosen surface.</li>
  <li>Run an offline test and capture the relevant log output.</li>
  <li>Restore the original file before testing another change.</li>
</Steps>
